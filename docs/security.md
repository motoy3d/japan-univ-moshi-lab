# セキュリティ点検（2026-11-22）

検証版の公開前に、利用者のデータ・費用・問題の品質を守る観点で点検した。次に点検するのは、課金を始めるとき、または大学・科目を増やすとき。

## 直したこと

| 項目 | 問題 | 対応 |
|---|---|---|
| 正解の流出 | 画面のコード（web/dist）に、全模試の正解・解説・本文がまるごと入っていた（志望校の画面が `content/index.ts` を読み込んでいたため）。ブラウザの開発者ツールで誰でも正解を読めた | 読み込みをやめた（バンドル 550KB → 379KB）。`npm run build` の最後に `scripts/check-bundle.ts` が、web/dist に問題データが入っていないかを毎回検査する |
| 回数制限の IP | API は CloudFront 経由なので、API Gateway が見る送信元は CloudFront の IP。そのままでは、多くの利用者が同じ IP として数えられる | `X-Forwarded-For` の末尾（CloudFront が付け足した接続元）を使う（`api/src/client-ip.ts`）。利用者が書ける先頭側は信用しない |
| 登録なし API の濫用 | 受験の提出・意見の送信はログイン不要なので、大量に送られると DynamoDB の書き込みと集計が汚れる | 端末ID ごと（1日30回）と IP ごと（1日300回）の上限。意見は IP ごとに1日100回 |
| 撮影採点の費用 | 1回あたり約0.06ドルの API 費用がかかる | 1人1日5回、サービス全体で1日300回の上限（最大で1日約18ドル）。AWS Budgets の月額予算アラート、Anthropic Console 側の月額上限も設定する（docs/deploy.md） |
| 退会 | データを消す手段がなかった（利用者に未成年が多く、削除の求めに応じる必要がある） | 設定画面の「退会する」で、受験記録・設定・撮影採点のジョブ・母集団の印と、Cognito のアカウントを削除 |
| バックアップ | 誤操作・障害で受験記録を失う恐れ | DynamoDB の PITR（35日分の任意時点に復元できる） |

## 設計上の守り（以前から、または今回追加）

- **認証・権限**
  - 認証は Cognito（Google またはメール）で、トークンは API Gateway の JWT オーソライザが検証する。
  - 運営の管理画面と `/api/admin/*` は、Cognito の `admin` グループの人だけが使える。権限は API 側で判定し、画面での出し分けは見た目だけ。
- **公開ルートの限定**
  - ログインなしで使えるのは5つだけ: 一覧、問題（正解なし）、統計、登録なし受験の提出、意見の送信。
  - それ以外の API はオーソライザが通さない。
- **入力の検証**
  - 解答は既知の設問IDだけに絞る。記述は60字まで。
  - 意見は種類と設問IDを検証し、500字までに切る。
  - 端末IDは `^[\w-]{8,64}$` の形だけを受け付ける。
  - 撮影の画像は1〜2枚、Base64 の文字種と長さで制限する。S3 のキーはサーバーが作る。
- **表示**
  - 利用者が書いた文章（意見）は React がエスケープして表示し、HTML として解釈しない。
- **ブラウザ側の防御**
  - CSP（インラインスクリプト禁止。接続先は自サイト・Cognito・Google アナリティクスのみ）を設定。
  - CloudFront の管理ポリシーで HSTS・nosniff・X-Frame-Options を付ける。
- **保存データ**
  - S3 はすべて非公開・暗号化。撮影の画像は読み取り後すぐ削除し、残っても1日で消える。
  - Anthropic の APIキーは Secrets Manager に置き、読み取り用 Lambda だけが読める。
- **デプロイ**
  - GitHub Actions から OIDC で行い、長期のアクセスキーは作らない。
  - デプロイ用のロールは CDK のブートストラップロールを引き受けることしかできず、`production` 環境のジョブからだけ使える。
- **監視**
  - Lambda の例外・5xx・4xx の急増・アプリのエラーログでメール通知。
  - API のアクセスログ（IP・UA・ユーザーID）は約3か月保管。
- **依存関係とコード**
  - CI で `npm audit`（high 以上で失敗）を実行する。
  - Dependabot で毎週更新を提案し、CodeQL で静的解析する。

## 残っているリスク（受け入れたもの・今後の課題）

| リスク | 影響 | 今の扱い |
|---|---|---|
| 正解は一度提出すれば分かる（結果画面に解説を出すため） | 正解を知った人が満点の答案を出して、偏差値の母集団を歪められる | 所要時間・解答率による除外、端末・IP の回数制限。偏差値は30人以上で表示。母集団が歪んだら、ログイン受験者だけに絞る |
| 端末ID は作り直せる | 登録なし受験の回数制限をすり抜けられる | IP の上限で抑える。学校など同じ IP の利用者が多い場合に誤って止めないよう、上限は大きめ |
| 所要時間は端末が申告する | 短時間の自動送信を長時間と偽れる | 同上 |
| 撮影の画像に書かれた文字による指示（プロンプトインジェクション） | 読み取り結果が歪む | 影響はその人自身の答えだけ。読み取り結果は本人が確認してから採点する |
| 管理画面の集計は全件を読む（Scan） | 受験が数万件を超えると遅くなり、10秒で打ち切られる | 検証期間の規模では問題なし。増えたら日次の集計テーブルに切り替える |
| デモ版（スマホ確認用の Artifact）には正解が含まれる | リンクを知っている人は正解を読める | デモは端末内だけで動く確認用。公開前に共有を止めるか、正解を含まない形に作り直す |
| API Gateway の URL に直接アクセスできる | CloudFront の WAF・レート制限を迂回できる | API 側の回数制限とスロットリング（毎秒20件）で抑える。必要なら API に WAF を付ける |
| 利用規約・プライバシーポリシーが雛形 | 法令上の不備 | 公開前に専門家の確認を受ける |
