# 設計書：検証版（登録なし受験・大問演習・撮影採点・計測）

作成: 2026-11-22 ／ 対象: 2026年12月上旬の公開 ／ 事業上の方針は事業企画書「検証方針」

検証したいのは一つだけで、慶應商の英語の模試を受験生が「もう1回受けたい」と思うかどうかである。そのために次の5つを作る。いずれも無料で提供する。

| # | 機能 | 目的 |
|---|---|---|
| 1 | 登録なし受験 | 最初の1回の壁をなくす |
| 2 | 大問演習（模試とは別の問題） | 15〜20分で試せる入口を作る。フル模試の初見性は守る |
| 3 | 撮影採点 | 紙で90分解く「本番どおりの受け方」を、採点まで完結させる |
| 4 | 意見の収集（目立たない形） | 問題の誤りと満足度を集める |
| 5 | 計測（GA4＋アプリ内の記録） | 2回目受験率・完了率を測る |

あわせて、偏差値は受験者が30人に達するまで表示しない。

## 1. 登録なし受験

### 画面と公開範囲

| 画面 | 変更前 | 変更後 |
|---|---|---|
| ホーム `/` | ログイン必須 | 公開。模試と大問演習の一覧。ログイン中なら志望校・カウントダウンも出す |
| 模試の案内 `/exams/:id` | ログイン必須 | 公開 |
| 受験 `/exams/:id/take` | ログイン必須 | 公開 |
| 印刷 `/exams/:id/print` | ログイン必須 | 公開 |
| 結果 `/results/:id` | ログイン必須 | ゲストの結果は `/results/local/:id`（端末内のデータを表示） |
| 成績分析・設定・撮影採点 | ログイン必須 | 変わらずログイン必須 |

### API

| メソッド・パス | 認証 | 内容 |
|---|---|---|
| `GET /api/exams`、`GET /api/exams/:id`、`GET /api/exams/:id/stats` | 不要 | 一覧・問題（正解なし）・統計 |
| `POST /api/guest/attempts` | 不要 | 採点して、結果と正解・解説をまとめて返す（`AttemptReview` と同じ形）。サーバーには匿名で記録する |
| `POST /api/feedback` | 不要 | 意見・満足度（4章） |
| それ以外 | 必要 | 従来どおり |

API Gateway では、上の公開ルートを JWT オーソライザなしで登録し、残りを `/api/{proxy+}`（オーソライザ付き）で受ける。HTTP API は具体的なルートを優先するので、公開ルートが先に当たる。

### 端末内の保存とログイン後の取り込み

- 端末ごとに匿名ID（`clientId`、ランダムな UUID）を `localStorage` に作る。個人を特定する情報は持たない。
- ゲストの結果（`AttemptReview`）は `localStorage` に最大10件保存する。正解・解説は提出後にしか届かないので、受験前に答えが見えることはない。
- ログインしたら、端末内の結果を `POST /api/attempts`（`imported: true`）で自分の履歴に取り込む。取り込んだ受験は偏差値の母集団に入れない（ゲスト受験の時点で入っているため）。

### 偏差値の母集団

- ゲストの初回受験も母集団に入れる。キーは `guest:<clientId>`。既存のボット対策（15分未満・解答3割未満は除外）はそのまま効く。
- `clientId` は作り直せるので完全ではないが、検証期間はこれで十分とする。公開後に偏りが見えたら、ログイン受験者だけに絞る。

### 偏差値の表示条件

`MIN_POPULATION_FOR_DEVIATION` を 2 から 30 に上げる。30人未満では偏差値・順位を出さず、「受験者が30人に達すると偏差値を表示します（現在◯人）」と表示する。

## 2. 大問演習（模試とは別の問題）

### 考え方

- 大問演習の問題は、フル模試には**出さない**。演習で解いた英文がフル模試に再び出ると、初見の実力が測れなくなるため。
- そのため、問題は「模試用」と「演習用」に分けてストックする。演習用のストックを多めに持つ。

### データ

| 項目 | 模試 | 大問演習 |
|---|---|---|
| ファイル | `content/exams/<id>.json` | `content/practice/<id>.json` |
| `kind` | `"mock"`（省略時） | `"practice"` |
| 大問の数 | 8 | 1〜2（同じ種類） |
| 時間 | 90分 | 15〜25分 |
| 設問番号 | 本番どおり（1〜46） | 1から振り直す |
| 原稿 | `scripts/build-keio-shogaku-NN.py` | `scripts/build-keio-shogaku-practice.py`（全演習を1本で生成） |

`ExamMeta` に次を足す。

- `kind?: "mock" | "practice"`
- `practiceType?: string`（「長文（論説）」「文法・語法」など、一覧での表示名）

### 重複の検査

`npm run validate` が、全模試・全演習の本文と設問文を正規化して比較する。8語以上の連続一致（8-gram）がほかの試験と重なったらエラーにする。演習の大問は、プロファイルの該当大問の形式（設問数・語数）に合っているかも検査する。

### ストックの目標

| 時期 | 模試 | 演習 |
|---|---|---|
| 公開時（12月上旬） | 2回 | 大問の種類ごとに1〜2題、計6題以上 |
| 1月中 | 3回 | 計15題以上 |

## 3. 撮影採点

### 流れ

```
[印刷して紙で受験] → 撮影画面（解答用紙A・Bを1枚ずつ撮る）
  → POST /api/photo-jobs（画像をS3へ、ジョブ作成）→ 読み取り用Lambdaを非同期で起動
  → 画面は GET /api/photo-jobs/:id を2秒ごとに確認
  → 読み取り結果を「答えの入力画面」に入れて表示（自信のない箇所は色付き）
  → 本人が確認・修正 → 「採点する」→ 通常の提出（mode: "paper"）
```

- **読み取った答えを、必ず本人が確認してから採点する。** AIの読み違いをそのまま点数にしない。
- 撮影はログインした人だけが使える（費用と濫用の管理のため）。1人1日5回まで。

### 構成

| 部品 | 内容 |
|---|---|
| S3 バケット `PhotoUploads` | 画像の一時置き場。**1日で自動削除**（ライフサイクル）。公開アクセスなし |
| `POST /api/photo-jobs` | 画像（JPEG、長辺2000px以下に端末で縮小、Base64）を受け取りS3へ保存。ジョブを DynamoDB に `PENDING` で作成し、読み取りLambdaを非同期で起動 |
| 読み取りLambda `PhotoReader` | S3から画像を読み、Claude に送って答えを JSON で受け取る。結果をジョブに保存して `DONE`（失敗時は `FAILED`）。タイムアウト2分 |
| `GET /api/photo-jobs/:id` | ジョブの状態と読み取り結果を返す（本人のジョブのみ） |
| APIキー | Secrets Manager `moshi-lab/anthropic`（`apiKey`）。CDK の `-c photoGrading=true` のときだけ作成・有効化する |

API Gateway の統合は最長30秒で打ち切られるため、読み取りは非同期にした。

### Claude への依頼

- モデル `claude-opus-5-5`。読み取りの正確さを優先する。拒否されたときのために、サーバー側の代替（`fallbacks: "default"`）を有効にする。
- 入力: 画像2枚（`image` ブロック、Base64）と、模試の設問一覧（マーク46問の番号、記述11問のラベル）。
- 出力: 構造化出力（JSON スキーマ）で、`marks: [{no, choice|null, confidence}]` と `writes: [{label, text, confidence}]`。
- 指示の要点:
  - マークは塗りつぶしの濃い番号を読む。二重マーク・判読不能は `null`、`confidence: "low"`
  - 記述は書かれた綴りをそのまま書き起こす。正しい綴りに直さない（採点が甘くなるため）
- 費用の目安は、画像2枚と設問一覧で入力約5千トークン、出力約2千トークンで、1回あたり約0.06ドル。1日5回の上限と、無料期間中の月間の総額で管理する。

### 個人情報

- 画像は1日で削除する。読み取り結果（答え）だけを残す。
- 解答用紙の氏名欄には名前を書かなくてよいと、撮影画面で案内する。
- 画像は Anthropic の API で処理される。プライバシーポリシーの委託先に記載する。

## 4. 意見の収集

### 問題ごとの意見（目立たない形）

- 結果画面の各問の解説の右下に、小さな吹き出しのアイコンだけを置く。読み上げ用ラベルは「この問題について知らせる」。「おかしい」「誤り」などの文字は、常時は表示しない。
- アイコンを押すと、小さな入力欄が開く。
  - 種類: 解説が分かりにくい／正解に納得できない／問題文・選択肢の誤字／難しさの感想／その他
  - 自由記述: 500字まで
- 送信後は「ありがとうございます。確認して改善します」とだけ表示する。

### 満足度

結果画面の得点の下に、1回だけ次を出す。

- 質問は「この模試（演習）をまた受けたいですか？」で、5段階で答えてもらう。
- 任意の一言（200字まで）を添えられる。
- 答えると畳まれ、同じ受験では二度と出さない。

### API・保存

- `POST /api/feedback` の本文: `{ examId, attemptRef?, questionId?, type: "question" | "rating", reason?, rating?, text?, clientId }`
- 保存先: `PK=FEEDBACK#<examId>`、`SK=<ISO日時>#<乱数>`。ログイン中ならユーザーID（sub）も記録する。
- 濫用対策は、API のスロットリングと文字数の上限で行う。運営者は DynamoDB を直接読む（管理画面は作らない）。

## 5. 計測

### Google アナリティクス（GA4）

- 測定ID（`G-XXXX`）は CDK の `-c gaId=...` で `config.json` に入れる。ID が無ければ読み込まない（ローカル・デモでは無効）。
- `gtag.js` は外部スクリプトとして読み込み、初期化は自前のモジュールで行う（CSP でインラインスクリプトを禁止しているため）。
- 設定: `allow_google_signals: false`、`allow_ad_personalization_signals: false`。SPA なので、画面遷移ごとに `page_view` を手動で送る。
- CSP に追加するもの:
  - `script-src`: `https://www.googletagmanager.com`
  - `connect-src` と `img-src`: `https://*.google-analytics.com`、`https://*.analytics.google.com`、`https://www.googletagmanager.com`

| イベント | パラメータ | 使い道 |
|---|---|---|
| `exam_view` | exam_id, kind | 模試・演習の案内を開いた |
| `exam_start` | exam_id, kind, mode（web / paper） | 開始率 |
| `exam_submit` | exam_id, kind, mode, score_rate, attempt_number | 完了率、2回目受験率（attempt_number ≥ 2） |
| `result_view` | exam_id | |
| `rating_submit` | exam_id, rating | 「また受けたい」 |
| `question_feedback` | exam_id, reason | 問題への指摘 |
| `print_open` | exam_id | 印刷の利用 |
| `photo_upload` / `photo_read_done` / `photo_read_failed` | exam_id | 撮影採点の利用と失敗率 |
| `login` / `sign_up_prompt_click` | — | 登録への導線 |

`attempt_number` は、端末内に数えた受験回数（ログイン中は履歴の件数）。

### アプリ内の記録

GA はブロックされることがあるため、正確な数はアプリ内の記録で確かめる。

- 提出数: ゲストの匿名記録と、ログインユーザーの受験記録。
- 2回目受験率: 同じ `clientId`（ゲスト）または同じユーザーの提出が2件以上ある割合。

集計は当面、運営者が DynamoDB からスクリプトで出す（`scripts/ops/kpi.ts`）。

## 6. 説明文の簡素化

- ホームの冒頭は2行にする。
  - 1行目: 「慶應義塾大学 商学部 英語の予想模試。本番と同じ形式・同じ90分。」
  - 2行目: 「登録なし・無料ですぐ受けられます。印刷して紙で解き、撮影して採点することもできます。」
- その下に「大問演習（15〜20分）」と「模試（90分）」の2つの入口を並べる。
- 料金・プランの記載はすべて外す。利用規約の料金条項は「無料」のままにする。

## 7. デプロイ

このセッション（クラウドのコンテナ）には AWS の認証情報を置かない。デプロイは GitHub Actions から行う。

- `.github/workflows/deploy.yml`: 手動実行（`workflow_dispatch`）。テスト・検証・ビルドのあと `cdk deploy` を実行する。
- AWS への認証は GitHub の OIDC で行い、長期のアクセスキーは使わない。IAM ロールの ARN はリポジトリ変数 `AWS_DEPLOY_ROLE_ARN` に置く。
- CDK のコンテキストは、リポジトリ変数・シークレットから渡す。
  - 変数: `GOOGLE_CLIENT_ID`、`GA_ID`、`PHOTO_GRADING`
  - シークレット: `ALERT_EMAIL`
- 初回だけ、利用者が AWS 側で準備する（手順は `docs/deploy.md`）。
  - OIDC プロバイダとロールの作成
  - `cdk bootstrap`
  - Google の OAuth シークレットと Anthropic の APIキーを Secrets Manager に登録
- 以後は、このセッションからワークフローを起動してデプロイし、結果を確認できる。
