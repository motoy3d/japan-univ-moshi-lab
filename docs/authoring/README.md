# 作問・検証の手順書

模試ラボの模試を、誰が作っても同じ品質になるように手順化したもの。慶應義塾大学 商学部 英語（第1回・第2回）を作った手順をそのまま記録している。ほかの大学・科目でも、1〜2章でプロファイルを作れば同じ流れで進められる。

形式の正確さがこのサービスの価値なので、**どの章も省略しない**。各章の終わりの「完了条件」を満たしてから次へ進む。

```
1. 本番の調査 ─→ 2. 入試プロファイル ─→ 3. 原稿 ─→ 4. 自動検査 ─→ 5. 曖昧さの点検
                                                                         │
     8. 公開 ←─ 7. 人による通し解き ←─ 6. 仮想受験者による試し解き ←──────┘
```

| ファイル | 役割 | コミット |
|---|---|---|
| `content/profiles/<大学-学部-科目>.json` | 入試プロファイル（形式と難しさの目標値） | する |
| `scripts/authoring/<大学-学部-科目>.py` | 作問の共通部品（設問・大問の組み立て、番号付け、正解位置の均等化） | する |
| `scripts/build-<大学-学部>-NN.py` | 各回の原稿。実行すると `content/exams/<id>.json` ができる | する |
| `scripts/validate-content.ts` | 形式の自動検査（`npm run validate`） | する |
| `scripts/quality_metrics.py` | 難しさの自動検査 | する |
| `content/personas/*.json` | 仮想受験者 | する |
| `scripts/simulate/*` | 仮想受験者の問題冊子の作成・採点 | する |
| `.local/reference/*.json`、本番のPDF・OCR | 本番の問題（較正用） | **しない**（著作権） |

## 0. 守ること（著作権と公平さ）

- 本文・設問・選択肢はすべて**オリジナル**。過去問・市販教材・Web記事の文章を流用しない。題材が実在の出来事でも、文章は一から書く。
- 実在の人物の発言をでっち上げない（引用符で発言を作らない）。事実関係（年・数字・地名）は確認したものだけを書く。
- 本番の問題文を AI に渡して「似た問題を作って」と頼まない。本番は**形式と難しさの数値を測るためだけ**に使い、そのデータは `.local/`（Git 管理外）かリポジトリの外に置く。大学は二次利用に許諾が必要と明示している。
- 大学名は「〜の出題形式を参考にした予想模試」として使い、大学が作成・監修したかのように見せない（`DISCLAIMER`）。

## 1. 本番の調査

1. 大学が公開している最新年度の問題・解答例を入手する（慶應は [入試問題の公開ページ](https://www.keio.ac.jp/ja/admissions/faculty/examinations/general-admissions/)）。公開されていない大問（著作権の関係で伏せられた長文など）も、大問の存在・設問数・形式は冊子から分かる。
2. 少なくとも直近3〜5年分の形式を確認する（赤本・予備校の解答速報・大学の公表資料）。毎年変わらない部分と、年によって揺れる部分を分ける。
3. 次を書き出す。
   - 大問の順番、設問数（マーク・記述）、試験時間、解答用紙の種類と切り替え位置
   - 設問番号の振り方（例：慶應商は長文ごとに「(i) 空所 → (ii) その他」の順に番号を振る）
   - 指示文・設問文の決まった言い回し（英語の設問文、"The answer is: [ n ]." など）
   - 書式（選択肢の番号の付け方、下線・空所の表記、語群の位置、例の示し方、末尾の《以下余白》）
   - 公表されている採点上の注意（例：同じ動詞を二回使うと得点にならない、〜ing 形は不可）
4. 本番のPDFが画像だけの場合は OCR する（rapidocr など）。**二段組みの選択肢は OCR の順番が崩れる**ので、選択肢は必ずページ画像で目視確認する。

完了条件: 大問ごとの形式表ができ、出典（URL・年度）が控えてある。

## 2. 入試プロファイル

`content/profiles/<id>.json` に、形式と難しさの目標を数値で書く（例: `keio-shogaku-eigo.json`）。

- **形式**: `durationMin`、`totalPoints`、大問ごとの `mark` / `write` の数、長文の語数の範囲、設問の種類ごとの数（`questionTypes`）、選択肢の数、正解位置の偏りの上限（`answerBalance.maxShare`）。
- **難しさ**（`difficulty`）: 本番を `quality_metrics.py` で測った値を中心に、少し幅を持たせる。
  - 長文の低頻度語の割合（wordfreq の Zipf < 4 の内容語の割合）
  - 読みにくさ（Flesch–Kincaid 学年。音節は独自の近似で数える）
  - 長文 (ii) の設問・選択肢の語数（時間の圧力の指標）
  - 中文空所の選択肢の平均 Zipf
- 慶應商 2026 の実測値: 長文I（学術書）低頻度語 19.2%・FK 16.7、長文III（論説）14.2%・10.4、(ii) 303〜447語、V 選択肢 Zipf 4.28。

完了条件: `npm run validate` がプロファイルを読み込み、既存の模試で通る。

## 3. 原稿

`scripts/build-<大学-学部>-NN.py` に書く。共通部品（`scripts/authoring/keio_shogaku_eigo.py`）を使うと、形式は自動的に本番どおりになる。

```python
from authoring.keio_shogaku_eigo import *
sections = []
sections.append(long_section("I", 1, 10, 段落のリスト, 注のリスト, 設問のリスト))
...
finalize(sections, "keio-shogaku-eigo-02", "第2回", seed=2028)
```

### 書き方の決まり

- 本文の記号: 空所 `{{b:N}}`、下線 `{{u:N|下線の語句}}`、記述の空所 `{{w:a}}`。N は**最終的な設問番号**（長文は空所が先、下線・内容一致が後）。
- 設問: `blank()`（空所）、`uline()`（下線部）、`detail()`（内容一致）、`title()`（表題）、`grammar()`、`cloze()`、`write()`。正解は何番に置いてもよい（`finalize()` が 1〜4 に均等に並べ替え、解説中の番号も書き換える）。
- 解説は日本語で、**正解の根拠（本文のどこか）と、各誤答がなぜ誤りか**を書く。
- 長文は3題のうち1題を学術的な文体（抽象名詞・長い文・低頻度語が多い）にし、残りは論説・物語。題材は回ごとに分野を散らす（経済史・技術史・社会問題など）。
- 文法問題は過去の回と論点を重複させない。第1回・第2回の論点は各原稿の `grammar()` を参照。
- 記述（VII 動詞の語形・VIII 名詞形）は、語群のどの語も**一つの空所にしか入らない**ように書き、`wordForms` に受け付ける語形をすべて列挙する（同じ動詞の二回使用の判定に使う）。

完了条件: スクリプトが例外なく実行でき、大問ごとの語数・問題数・配点の表示が想定どおり。

## 4. 自動検査

```bash
python3 scripts/build-keio-shogaku-02.py
npm run validate                                   # 形式（プロファイルとの一致、正解の偏り、語形の表など）
python3 scripts/quality_metrics.py content/exams/keio-shogaku-eigo-02.json   # 難しさ
npm test && npm run typecheck
```

`quality_metrics.py` は Python の `wordfreq` が必要（`pip install wordfreq`）。✗ が出たら原稿を直す。よく使う直し方:

| 症状 | 直し方 |
|---|---|
| 低頻度語の割合が低い | 一般的な語を同じ意味の硬い語に置き換える（opened it up → dismantled it、secret → proprietary） |
| FK が低い | 文をつなげて長くする、抽象名詞で言い換える |
| (ii) の語数が少ない | 選択肢を長く、紛らわしくする（本文の語を使いつつ一部だけ違う、言い過ぎ、因果の逆転） |
| V の選択肢が易しい | 形の似た語（appreciate / depreciate、profile / proverb）や、意味は知っていても語法で外れる語を入れる |
| 長文の語数が足りない | 段落に具体例を一文足す（論旨を変えない） |

完了条件: すべて ✓。

## 5. 曖昧さの点検（正解が一つに決まるか）

自動検査では見つからない。作問者自身が**全設問・全選択肢**を、次の観点で一つずつ確認する。第1回では5問、第2回では2問をここで直した。

- [ ] 誤答の選択肢を空所に入れても、文法的・意味的に成り立ってしまわないか（口語・英国用法・慣用句を含めて）。例: "the course fee is not refunded" は refundable と同じく成立する → 差し替え。
- [ ] 誤答の内容が、本文から**言えてしまわないか**（"almost as highly as experts" から「専門家の作品のほうを高く評価する」が導けてしまう、など）。
- [ ] NOT 問題で、正解以外の3つが本文に確かに書いてあるか。
- [ ] 正解の根拠が本文のどこにあるか、解説に書けるか。書けないなら設問が悪い。
- [ ] 記述問題で、語群の別の語や別の語形も入ってしまわないか。
- [ ] 解説の選択肢番号が、並べ替え後の番号と一致しているか（`finalize()` が書き換えるが、目視でも確認）。
- [ ] 実在の事実（年・数字・人物）が正しいか。

完了条件: 気になった設問をすべて直し、4章の自動検査をもう一度通した。

## 6. 仮想受験者による試し解き（難しさの較正）

作問者は正解を知っているので、難しさを正しく判断できない。そこで「正解を知らない第三者の受験生」を AI で再現し、**本番の過去問と模試を同じ受験者に解かせて、得点率が同程度になるか**を確かめる。

### 受験者プロファイル

`content/personas/*.json`（詳しくは `content/personas/README.md`）。現在は偏差値55・62・68の3人。ファイルを足せば増やせる。

- 語彙: 語の頻度（Zipf）から「知っている確率」を決め、知らない語は冊子で `[?]` に伏せる（同じ語はどこでも同じ扱い）。
- 読解の破綻: 知らない語が一定数以上ある文は「意味が取れなかった文」として丸ごと伏せる（AI は伏せ字を文脈で補ってしまうため、文単位で情報を消す）。
- 文法: 文法問題ごとに、受験者がその論点を知っているかを確率で決め、知らない問題には「あやふや」の印を付ける。
- 時間: 読む速さと1問あたりの時間から、90分で着手できない大問を【時間切れ】にする（本文を伏せる）。
- 文法の苦手事項と解き方の癖: 冊子の冒頭に書き、解答者に守らせる。

### 受験者の較正（新しい受験者を足したとき・試験の種類を増やしたとき）

先に**本番の過去問だけ**を解かせ、得点率がその偏差値帯の受験生として妥当になるまで `vocab.zipf50`・`sentenceCollapse`・`grammarKnown` を調整する。そうしてから模試を解かせる。受験者を本番で較正せずに模試を比べると、全員が満点近くになって差が見えない。

### 手順

```bash
# 1) 問題冊子を作る（答えは含まない）。本番の公開部分は .local/reference/ に置いておく
PY=python3 scripts/simulate/make_all_packets.sh /tmp/sim
# 2) 冊子1冊ごとに、新しい会話の AI（前後の文脈・正解を一切知らない）に解かせる。
#    指示: 「この冊子だけを読み、冒頭の受験者になりきって解き、最後の JSON を出力して保存せよ。
#           [?] の語を復元しない。他のファイルや Web は見ない。ファイルの読み書き以外のツールは使わない」
# 3) 採点と集計
python3 scripts/simulate/score.py grade content/exams/keio-shogaku-eigo-02.json dev62 /tmp/sim/out/ex02-dev62.txt /tmp/sim/res/ex02-dev62.json
python3 scripts/simulate/score.py report /tmp/sim/res/*.json --md docs/quality/simulations/<日付>.md
```

- 本番は公開部分（慶應商なら I・III・IV・VI の2題・VIII）しかないので、比較は**共通部分の得点率**（`compareRate`）で行う。持ち時間は、欠けている大問にかかる時間を模試で見積もって縮める（`--like`）。
- 判定の目安: 同じ受験者の共通部分の得点率が、本番と模試で **±8ポイント以内**なら合格。偏差値の高い受験者ほど得点率が高い（順序が保たれている）ことも確認する。
- 大問別に見て、模試だけ極端に易しい・難しい大問があれば、その大問を4章の表の方法で調整し、もう一度試す。
- 解答者の `notes`（難しかった所・時間配分の感想）と、`confidence` が「確信」なのに誤答した設問は、曖昧さの手がかりになるので5章に戻って確認する。
- 本番のデータを使った結果は、数値（得点率）だけをレポートに書き、本番の英文・選択肢は書かない。

### 限界（レポートにも明記する）

- 語彙は英語圏の語の頻度で近似しているため、日本の単語帳で習う語（aloud、accuse など）を知らない扱いにすることがある。本番と模試に同じ基準を当てているので、比較には使える。
- 解答者は AI なので、伏せた語の推測や消去法が実際の受験生より上手な可能性がある。受験者間・試験間の**相対比較**として使い、絶対的な得点予測には使わない。
- **AI の解答者は、伏せ字があっても消去法と文脈で正解してしまう。** 2026-11 の試行では、偏差値62・68の受験者は本番でも模試でも 89〜100% になり、差が出なかった（`docs/quality/calibration-keio-shogaku-eigo.md`）。差を測れるのは偏差値55程度の受験者で、比較もその受験者で行う。偏差値と得点の対応（絶対的な水準）は、公開後の実際の受験データで較正する。
- 1回の試行はばらつく。差が小さいときは、同じ冊子を別の会話でもう一度解かせて平均を取る。

完了条件: 較正レポート（`docs/quality/calibration-*.md`）を書き、目安を満たした。満たさない場合は調整して再試行した。

## 7. 人による通し解き

公開前に、正解を知らない人（大学生・講師など）に紙で90分通して解いてもらい、時間・難しさ・誤植・曖昧さの指摘を受ける。指摘は5章の観点で直す。（未実施の回はレポートにその旨を書く。）

## 大問演習（模試とは別の問題）

大問1つ（または同じ種類の2つ）の演習は `scripts/build-keio-shogaku-practice.py` に書き、`finalize_practice()` で `content/practice/` に出力する。番号は 1 から振る。演習の英文は模試に再掲しない（`npm run validate` が本文と選択肢の8語連続一致で検査する）。各大問はプロファイルの同じ大問の形式（設問数・語数・(i)/(ii) の構成）に合わせる。手順は模試と同じく 4〜6 章を通す。

## 8. 公開

1. `content/index.ts` に追加（模試は `MOCKS`、演習は `PRACTICE`）。模試は `content/admissions.ts` の該当学部の `mockExamIds` にも追加。
2. 4章の検査をすべて実行。
3. 印刷見本を更新（`docs/samples/`）。デモを使う場合は `npm -w web run build:demo` → `node scripts/build-demo-artifact.mjs <出力.html>`。
4. 品質レポート（`docs/quality/review-<id>.md`）に、形式・数値・修正した設問・試し解きの結果を残す。
5. コミット。本番のデータ（`.local/`）が含まれていないことを `git status` で確認する。

## 世界史（慶應 商学部）の作り方

英語と同じ 1〜5 章の流れで作る。違うところだけ書く。

- 形式は `content/profiles/keio-shogaku-sekaishi.json`（`format: "history-blank-bank"`）。大問3題。各大問は日本語のリード文と、問1（空欄に入る語句を、11 から番号の付いた語群から選ぶ。2桁の番号を2つの解答欄にマーク）、問2以降（語句の記述・短い論述）。
- 原稿は `scripts/build-keio-shogaku-sekaishi-NN.py`、共通部品は `scripts/authoring/keio_shogaku_sekaishi.py`。
  - 本文の空欄は `[[キー]]` と書き、`blank("正解の語句", 分野, 解説)` を対応させる。番号（(1)(2) の組）は出てきた順に自動で振る。
  - 語群は `(語句, 読み)` のリスト。読みで五十音順に並べ、11 から番号を付ける（数字 → 英字 → かな）。正解の語句をすべて含め、残りは紛らわしいが条件で外れる語にする。
  - 下線部は `{{u:a|語句}}`、記述の空欄（あ）は本文にそのまま書く。設問は `write()`（語句。正解の別表記を並べる）と `essay()`（論述。模範解答・字数・採点の観点）。
  - 組み立て時に、語群の語が本文にそのまま出ていないか、模範解答が字数以内かを検査する。
- **事実の確認を必ず行う。** 年・人名・出来事を1項目ずつ出典（Wikipedia などのページを開いて照合）で確かめ、確かめられないことは書かないか、言い切らない表現にする。確認の結果は品質レポートに残す（`docs/quality/review-keio-shogaku-sekaishi-01.md` が例）。
- 論述は自動採点しない（`selfGrade`）。結果画面で模範解答と観点を示し、利用者が自分で点を付ける。偏差値は自動採点の得点だけで計算する。
- 撮影採点は2桁の番号の読み取りに未対応なので、世界史の模試では使えない。
